# 手机浏览器验收

使用 Python Playwright 和 Chromium 验收 390 × 844 的手机流程。开发服务启动后运行：

```sh
python tests/browser_acceptance.py
# 其他本地端口：
python tests/browser_acceptance.py --base-url http://127.0.0.1:5173
```

当前云环境已提供 Python Playwright 和 `/usr/bin/chromium`。在其他环境中可通过受信任的软件源安装这些测试工具；它们不是网站生产依赖。

`fixtures/dida-official-examples.json` 来自供应商文档 `https://didatickettest.wysiwysi.com/api/distribution/docs/` 的 OpenAPI 200 响应示例：城市、国家、商品列表、详情、SKU 日历、套餐额外信息、可用性检查和订单验证。

这些示例仅用于浏览器 route 拦截，不能作为正式商品内容。图片 URL 保留文档示例 `https://cdn.example/banner.jpg`，测试在该 URL 返回标记为测试的 SVG 图片。日历日期平移到请求窗口内，另加入库存为 0 和报价上涨的契约状态。正式站点不加载这些文件。

本站 `/api/catalog/prices` 起价摘要的模拟响应取官方成人 SKU 日历示例中的 USD 79.00，用于检查商品卡片展示“价格 + 起”；它不是供应商原生接口示例，也不替代服务端对跨套餐最低价的契约测试。

测试拦截所有 `/api/*` 请求，阻止外部请求，并在遇到未匹配的 API 时失败。因此测试不需要密钥、不创建供应商订单、不调用支付接口。截图保存于已忽略的 `artifacts/browser/`，画面上的商品和图片为官方示例，不代表真实供应商联调。

自动验收覆盖目的地必选、“查询”按钮、首页日期与人数输入及收藏入口已移除、目的地搜索参数、商品卡片起价、API 商品标题和图片渲染、错误后重新加载、详情页日期与数量选择、零库存日期不可选、日历价格、必填英文姓名、动态预订补充信息和旅客证件字段、预订草稿及报价变化后的二次确认。

7 项模拟场景也检查真实验证接口要求的序列化：文本回答为 `{key,content}`，选项回答保留 `{key,selected:[...]}`，不展开为扁平子字段；即使旅客规则为空，也按照 SKU 数量发送以 1 起始的 `index` 旅客条目。直接文本、直接选项及空旅客规则的结构已通过真实商品验证；官方示例中的多层护照规则结构仍是按规则树推断的测试，不能视为复杂旅客字段已经完成真实联调。

所有预订提交均使用测试拦截响应。本验收只证明页面对公开接口契约的处理；动态附加信息的真实供应商接受情况、实时库存、订单创建和收银台跳转还需要具备安全凭据及真实接入契约后单独验证。

具备安全服务端凭据后，可单独运行真实数据的手机浏览检查：

```sh
python tests/live_browser_smoke.py --base-url http://127.0.0.1:5175 --product-code 105
```

该脚本读取真实城市、商品、详情、日历和附加信息，允许只读 `availability-check`，在联系人仍为空的预订页面停止。浏览器直接阻断订单验证、订单创建、支付及其他写入请求，不打印或读取凭据。运行时使用环境提供的 HTTP 代理，保留证书验证。真实数据截图命名为 `*-live.png`，结果保存至 `artifacts/browser/live-read-only-report.json`；与官方示例截图分开。

另有明确开启演示验证的独立脚本：

```sh
python tests/live_cashier_smoke.py --base-url http://127.0.0.1:3013
```

该脚本先确认 `/api/health` 为已配置且固定 `validate` 模式，使用合成联系人填写真实商品 105 的表单。浏览器只允许本地库存验证、订单验证和验证草稿接口；服务端的草稿接口只转发供应商订单验证，不能创建或支付供应商订单。最终检查收银台的 DEMO 标记、草稿编号、真实报价与尚未生成订单／收取费用的提示。截图为 `final*-live.png`，结果为 `live-cashier-report.json`。

浏览器保留 TLS 校验，使用平台提供的代理及已安装的公共 CA。此云环境的 Chromium 还需要正常读写既有 `/home/agent/.pki/nssdb`；仅允许工作区写入的文件系统沙箱会阻止 NSS 初始化／数据库写入，导致 CA 已受信任时仍出现 `ERR_CERT_AUTHORITY_INVALID`。经受控的执行权限审查允许访问既有 NSS 库后，同一图片在正常 TLS 验证下返回 200 并渲染成功。由运行工具授予这项必要的文件系统访问，再运行上面的 CLI；脚本不会自行提权。不要重设 `HOME`、关闭证书校验、覆盖既有 NSS 数据库，或因该沙箱现象重复导入 CA。
